# 危化试剂库房管理台

纯前端（React 19 + TypeScript + Vite，localStorage 持久化）的危化试剂库房管理演示。

## 启动

```bash
npm install
npm run dev      # http://localhost:62003
```

## 模型

- **试剂**：CAS、危险特性、反应组（强氧化剂/强酸/强碱/重金属盐/惰性）、单位、剩余量预警线、额外禁忌组
- **批次**：入库日、标称效期、开封日、开封后稳定天数（实际效期 = min(标称, 开封日+稳定天数)）、初始/剩余/预留量、状态（在库/冻结/召回/用尽）
- **库位**：安全柜分区，允许反应组白名单、容量，与既有批次做混存相容校验
- **单据状态机**：待预留 → 已预留 → 已发放 → 部分归还 → 已消耗 → 已关闭；分支 已取消 / 召回冻结（只读终态）

## 关键规则

- **FIFO 跨批次占用**：按实际效期升序（同日按入库日）跨批次扣减；过期/冻结/召回批次不参与，只在拦截列表中说明
- **整单事务**：所有写操作在深拷贝快照上执行，任一步失败（库存缺口、效期、相容、并发被抢、超额归还等）整体回滚，提交前再跑不变量自检（负库存/预留超卖）
- **效期边界**：到期当日仍可发放，次日判过期并在预留/发放环节拦截
- **权限**：研究员（申请/归还/消耗/取消本人单）、库管员（预留/发放/关闭/驳回）、管理员（含批次冻结/召回）
- **幂等**：动作携带幂等键，同键重复提交直接判无效
- **并发**：请求按到达顺序串行抢占，仅可整体满足的请求成功，库存绝不出现负值（工作台内置并发压测按钮）
- **召回**：批次召回时冻结相关申请/预留单并释放预留，单据进入只读冻结态，审计轨迹完整保留

## 页面

效期风险看板、领用工作台、库存批次（登记/冻结/召回）、库位视图、审计档案（全量操作时间线 + 单据只读档案 + 召回令）。

## 验证

- `selftest.ts`：引擎纯函数自检（54 项，Node 直接跑）
- `e2e.ts`：Playwright 浏览器端到端（46 项），覆盖跨批次分配、效期边界、并发冲突、回滚/重复提交/越权、召回冻结与刷新恢复
